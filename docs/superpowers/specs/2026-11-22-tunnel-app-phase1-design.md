# tunnel-app 一期设计

日期:2026-11-22
状态:已实现(桌面一期);手机端未开始。真机验证见 `desktop/README.md`
交互原型:`docs/design/desktop-prototype-v12.html`(浏览器直接打开;左上角切换「首次打开 / 已配置」两个演示场景)

## 1. 意图

用户在公司电脑、家里的 macOS / Linux / Windows 机器、Android / iOS 手机之间,通过只运行 sshd 的 VPS 互相访问。底层工具 [tunnel](https://github.com/pangxincheng/tunnel) v1.1.0 已支持**按名字转发**:家里机器把自己挂到 VPS 上的 `<socket目录>/<name>.sock`,客户端按名字连过去。

现在的痛点是:每台机器都要手写 `tunnel.toml`、开终端运行 `tunnel server/client`,不知道哪些机器在线,也没有开机自启。tunnel-app 是 tunnel 的**跨平台图形化管理软件**:一个桌面 App 既能把本机共享到 VPS,也能连接 VPS 上的其他设备;手机端一期只看在线状态。

## 2. 目标 / 非目标 / 反目标

**目标(一期)**
- 桌面 App(Windows / macOS / Linux):管理多台服务器(VPS);每台服务器上「共享这台电脑」与「连接其他设备」;设备在线状态;本机端口固定;常用命令一键复制。
- 共享支持两种运行方式:登录后运行(三个系统)、无人登录时也保持(macOS / Linux 系统服务)。**(用户定)**
- 命令行 `tunnel install / status / uninstall`,供无图形界面的 Linux 服务器使用,也是桌面 App 共享功能的底层。**(用户定)**
- 手机 App(Android / iOS):只看各服务器上的设备在线状态。**(用户定)**
- 主题色、浅色 / 深色、简体中文 / English。**(用户定)**

**非目标(一期不做)**
- VPS 上的常驻管理服务、网页后台、掉线通知、历史记录。**(用户定:只要「方案 A」)**
- 远程控制其他设备(重启隧道、看日志);手机上连接设备、内置终端、VPN 扩展。
- 写入 `~/.ssh/config` 或生成 ssh 别名。**(用户定)**
- 随机 / 自动本机端口。**(用户定)**
- Windows 的系统服务(无人登录时保持)。**(用户定)**
- 流量伪装。
- 带口令的私钥与 ssh-agent。「测试连接」遇到带口令的私钥时明确提示:「Tunnel 需要一把没有口令的私钥。可以为它单独生成一把:`ssh-keygen -t ed25519 -N "" -f ~/.ssh/tunnel_ed25519`,并把公钥加到服务器的 `~/.ssh/authorized_keys`」。**(用户定)**
- 清理离线设备的残留记录(服务器上旧的 `<name>.json`)。一期不提供界面操作,需要时在 VPS 上手动删除;留给后续的服务器端管理系统。**(用户定)**

**反目标(做出来也算失败)**
- 一期在 VPS 上部署任何自研进程(一期 VPS 必须保持「只跑 sshd」;后续计划另做服务器端管理系统,届时单独设计)。
- 用户需要记忆或手写 socket 路径、端口号以外的连接细节。
- 设备暂时离线时,App 擅自关掉用户开着的转发。
- 主机公钥不经用户确认就被信任(破坏 tunnel 的钉住模型)。

## 3. 约束

- 底层协议与安全模型沿用 tunnel:SSH 公钥认证、钉住 VPS 主机公钥、Unix socket 按名字转发、VPS sshd 需 `StreamLocalBindUnlink yes`。
- 同一服务器上,共享端与连接端必须使用**同一个 VPS 账户**(socket 目录 700,在 `$HOME/.tunnel/sockets`)。
- 技术栈 **(用户定,方案 D)**:桌面 **Wails v3**(实际使用 v3.1.0;Go 后端 + React 18 / TypeScript 前端;React 沿用模板的 18 **(设计判断)**);手机 **React Native(Expo,development build)**,Go 核心经 **gomobile** 接入(Android `.aar` / iOS `.xcframework`),桥接用 Expo Modules API,接口收发 JSON 字符串。
- Go 核心逻辑(转发、服务器连接、设备列表、服务安装)复用 / 扩展 `github.com/pangxincheng/tunnel` 包;tunnel-app 不复制转发代码。
- 仓库:`tunnel-app`(本仓库,`desktop/` + `mobile/`);核心与 CLI 改动落在 `tunnel` 仓库,各自记 CHANGELOG。

## 4. 方案选择

### 4.1 管理方式
| 方案 | 取舍 | 结论 |
|---|---|---|
| A. 客户端内置管理:读 VPS 上 socket 目录与设备信息文件 | VPS 仍只跑 sshd;只能「看」,没有通知 / 历史 / 网页 | **采用(用户定)** |
| B. VPS 常驻管理服务 + 网页后台 | 功能全;多一个公网服务要加固,工作量数倍 | 否 |

设备详情的取得方式:A(设备信息文件,采用)/ B(控制 socket,需自建认证,否)/ C(经设备自身 sshd 执行命令,二期远程控制再考虑)。

### 4.2 界面技术
| 方案 | 取舍 | 结论 |
|---|---|---|
| Flutter 全平台 + Go FFI | 一套语言;但桌面 / 手机设计语言不同,界面仍需分别设计 | 否 |
| **Wails v3(桌面)+ RN Expo(手机)+ Go 核心** | 桌面直接调 Go 无桥接;两端都是 TS/React 思路;手机需原生桥接 | **采用(用户定)** |
| Fyne 纯 Go | 最简单,界面精致度受限 | 否 |

### 4.3 桌面信息架构(经 12 版原型收敛)
- 顶部「连接设备 / 共享本机」两个页签 → 否:VPS 被藏进设置,主线绕路。
- **以服务器为中心**:左侧服务器列表,右侧该服务器的「共享这台电脑」+「连接其他设备」。**(用户定)**
- 竖屏小窗 → **横屏双栏,可调整大小、可全屏**;设置 / 添加服务器用弹窗。**(用户定)**
- 设备配置:行内展开 → 配置弹窗 → **行内只改端口,弹窗只放命令**。**(用户定)**

## 5. 架构

```
tunnel 仓库(Go)
 ├─ tunnel/            核心库:转发、socket 解析(已有)+ 本期新增:设备信息文件、设备列表、多转发会话、服务安装
 └─ cmd/tunnel         CLI:server / client / version + 本期新增 install / status / uninstall

tunnel-app 仓库
 ├─ desktop/           Wails v3:Go 服务层(薄适配,调用 tunnel 包)+ React/TS 前端
 └─ mobile/            Expo:TS 界面 + 原生模块(Kotlin / Swift)→ gomobile 生成的 Go 库
```

### 5.1 进程模型(设计判断)
- **连接其他设备(client)**:在桌面 App 进程内运行。App 窗口关闭 = 隐藏,不退出;托盘 / 菜单栏图标保留,右键菜单含「打开」「退出」。退出 App 即停止所有转发。
  - 所有平台都有应用菜单「退出」(Cmd+Q / Ctrl+Q),没有托盘的 Linux 桌面靠它退出。**(设计判断)**
  - 登录时启动 Tunnel(7.4 设置)由 App 自己注册:macOS LaunchAgent、Linux `~/.config/autostart` 的 `.desktop`、Windows 注册表 Run 项;注册失败时保留原设置并提示。**(设计判断)**
- **共享这台电脑(server)**:**两种运行方式都不在 App 进程内**,而是由 App 调用 `tunnel install` 安装成独立的服务进程(用户级或系统级),App 只是控制面板。这样:
  - 退出 App 不影响共享;
  - 命令行与图形界面操作的是同一个服务,状态一致;
  - 「登录后运行」= 用户级服务(macOS LaunchAgent、Linux `systemd --user`、Windows 任务计划程序「登录时运行」任务,见第 9 节第 4 项);「无人登录时也保持」= 系统级服务(macOS LaunchDaemon、Linux systemd 系统服务)。
- **服务控制通道(设计判断)**:每个共享服务进程开一个本机控制 socket(macOS / Linux 为 Unix socket,Windows 为命名管道),**属主是安装它的用户**(system 模式由 install 记录该用户并在服务启动时 chown),权限 600。App 不需要管理员权限即可通过它:读取状态、暂停 / 恢复(对应「断开 / 连接」服务器)、触发「重试」、改设备名字。只有安装、卸载、切换运行方式需要管理员授权。
- 暂停状态由服务自己持久化(写在它自己的状态目录),重启后保持暂停;暂停中的服务进程保持运行但不连接 VPS。
- `tunnel` CLI 由桌面 App 安装包附带(与 App 同版本的独立可执行文件;macOS `.app` 与 Windows 安装包、Linux deb / rpm 已带,**AppImage 暂未带,共享功能在 AppImage 上不可用 [pending]**)。找不到附带的 CLI 时 App 仍能启动,共享操作报错。App 启动时比较已安装服务的版本,较旧则提示「更新共享服务」(system 模式需授权一次)。**(设计判断)**

### 5.2 每台服务器一条 SSH 连接(设计判断)
同一台服务器上的多个转发与设备列表刷新,复用**一条** SSH 连接(现有 `tunnel.Client` 一个连接只建一个 establish,需在核心库新增「一个连接承载多个转发、可动态增删」的会话 API)。共享服务(独立进程)自己持有另一条连接。

## 6. 数据

### 6.1 设备信息文件(VPS 上,与 socket 同目录)
- 路径:`<socket目录>/<name>.json`,由共享端每次连上 VPS 时写入(覆盖)。
- 字段(只放非敏感信息):

| 字段 | 说明 |
|---|---|
| `device_id` | 由操作系统的机器标识派生(macOS `IOPlatformUUID`、Linux `/etc/machine-id`、Windows `MachineGuid`,加固定前缀后取 SHA-256 前 16 字节的十六进制),**全机器唯一**,App、用户级与系统级服务算出的都相同,无需存储。用于区分「同名的是不是我自己」。**(设计判断)** |
| `name` | 设备名字 |
| `hostname` / `os` / `os_version` / `arch` | 展示用 |
| `tunnel_version` | 展示 / 排错 |
| `started_at` | 本次共享开始时间,用于「在线 3 天」 |

- 写入方式:经 SFTP 或 exec(与 socket 目录解析一致;账户禁止执行命令时用 SFTP,实现者择一并保证 nologin 账户可用)。
- 离线后文件保留,用于显示「最后在线」;是否在线**不看文件**,看 socket 能否连通(见 6.2)。

### 6.2 设备列表与在线判断
- 列表:读取 socket 目录下所有 `*.json`。
- 在线:对每个 `<name>.sock` 发起 `direct-streamlocal` 连接,能连通即在线,随即关闭。代价:每次探测都会在目标设备 sshd 留下一条未完成认证的连接记录;实现者可改用更轻的探测,但判定结果须等价。
- 「最后在线」:离线设备取 json 的 `started_at` 与上次探测在线的时间中较晚者(App 本地记录最近一次探测在线时间)。
- 刷新:窗口打开时立即刷新;之后每 30 秒;服务器断开 / 无法连接时停止刷新。
- 设备列表持久化在本机配置中(含获取时间):服务器已断开或无法连接时仍显示上次的设备列表并标注年龄(7.3)。**(设计判断,7.3 的横幅要求设备列表仍可见)**

### 6.3 本机配置(桌面 App)
- 位置:各系统的用户配置目录(Go `os.UserConfigDir()`)下 `tunnel-app/`。
- 内容:服务器列表(含上次的设备列表缓存,本地名称、地址、SSH 端口、登录用户、私钥**路径**、已信任的主机公钥、是否「已断开」)、每个设备的本机端口(键:服务器名称 + 设备名)、每台服务器上开着的转发、外观与通用设置。**不保存私钥内容。**
- 后端保存 / 修改服务器时校验 `host_key` 可解析,为空或无效一律拒绝(前端「先测试并信任」的门槛之外再兜一层)。
- 共享配置(设备名字、运行方式)以已安装服务为准,App 从服务读取。

### 6.4 命名规则
- 服务器名称、设备名字统一规则:`^[A-Za-z0-9][A-Za-z0-9._-]{0,63}$`。
- 服务器名称只在本机使用,本机内唯一;改名时 App 负责迁移已安装的服务与本地配置。
- 设备名字在同一服务器上唯一(见 7.4)。
- 服务名:`tunnel-<服务器名称>`(每台服务器一个共享服务,一台机器可同时共享到多台服务器)。设备名字只保存在服务配置中,改名不改变服务身份。**(设计判断,tunnel 终审后确定)**

## 7. 桌面端界面

原型 v12 是视觉与交互的参照;以下为规范。

### 7.1 窗口
- 横屏双栏,默认约 940×600,最小 720×460,可调整大小、可全屏。标题栏:macOS 用隐藏式标题栏,红绿灯在左上角、压在侧栏顶部(侧栏顶部是 46px 高的拖动区,左侧留约 78px 给红绿灯);Windows / Linux 用系统标题栏,窗口按钮在右上角。**(用户定)**
- 左栏 240px:服务器列表;底部「＋ 添加服务器」与设置齿轮。右栏:选中服务器的详情;顶部显示服务器名称与 `用户@地址`。
- 首次打开(无服务器):右栏空状态「添加第一台服务器」+ 主按钮。

### 7.2 服务器列表(左栏)
- 每行:状态点、名称、摘要「已连接 x　在线 y」(「已连接」只计真正接通的转发)。
- 状态:正常(主题色点)、本机共享失败(红点)、无法连接(红点 + 红字「无法连接」)、已断开(灰点 +「已断开」)。
- 行内操作(悬停、选中或键盘聚焦时显示):**编辑**(打开服务器设置弹窗)、**连接 / 断开**、**删除**(先确认)。**(用户定)**
- 断开:停止这台服务器上的共享与转发,保留各开关状态;重新连接后自动恢复。断开状态持久化,重启 App 后保持。
- 「共享这台电脑」的开关关闭 = **暂停**共享服务(服务保留、不再连接 VPS),不卸载;只有删除服务器、改名迁移或切换运行方式才卸载 / 重装。**(设计判断)**
- 删除确认文案:「删除 X？会停止在它上面的共享和 N 个转发，并删除这台服务器在本机的配置。服务器上的数据不受影响。」默认焦点在「取消」。删除同时卸载这台服务器对应的共享服务。

### 7.3 服务器详情(右栏)
自上而下:状态横幅(按需)→ 共享这台电脑 → 连接其他设备。

**状态横幅**
- 无法连接:红色横幅「无法连接 X:<原因>。设备列表是 <时长> 前的。N 秒后重试」+「立即重试」;下方设备列表变灰但可见。
- 已断开:灰色横幅「已断开 X:共享和转发都已停止,开关状态会保留」+「连接」;下方内容变淡且不可操作。

**共享这台电脑**(整块常驻展开,不做弹窗)**(用户定)**
- 首行:状态点、设备名字 +「这台电脑」、状态(未共享 / 正在连接 / 已就绪 / 连接失败,已停止重试 / N 秒后重试),行尾开关。
- 失败时首行下方出现错误说明(原因 + 可执行的排查命令)与「重试」「查看日志」。
- 设备名字:输入框,副标题「在 X 上需唯一」。
- 无人登录时也保持共享:开关,副标题「开机即在线,无需登录」;仅 macOS / Linux 显示;打开时触发系统管理员授权。
- 底部状态行:本机 SSH 服务检测结果(见 7.6)。

**连接其他设备**
- 每行顺序(用户定,依阅读顺序 = 任务顺序):**身份**(状态点、名字、系统 + 在线时长)→ **连接**(本机端口 + 开关)→ 分隔线 → **使用**(命令按钮)。
- 本机端口:每个设备第一次出现时从 5102 起分配一个未占用端口,之后固定;点击数字原地变为输入框,回车保存、Esc 取消;校验 1024–65535 且不与本 App 已分配的端口冲突,错误显示在行下方。转发开着时改端口 = 重启该转发。
- 开关:打开 = 本机 `127.0.0.1:<端口>` 开始监听并转发到该设备。端口被其他程序占用时打开失败,行下方提示并保持关闭。
- 离线设备:**不能打开**(开关禁用)。**(用户定)** 已打开的转发在设备掉线后**保持打开**,显示「离线,上线后恢复」,用户可手动关闭。**(设计判断)**
- 命令按钮:打开「连接命令」弹窗。

### 7.4 弹窗
- **连接命令**:标题「<设备> 的连接命令」;副标题说明转发是否已打开。列表(每条单独「复制」):
  - ssh `ssh -p <端口> <USERNAME>@127.0.0.1`
  - scp 上传 `scp -P <端口> <本地文件> <USERNAME>@127.0.0.1:<路径>`
  - scp 下载 `scp -P <端口> <USERNAME>@127.0.0.1:<路径> <本地目录>`
  - rsync `rsync -av -e "ssh -p <端口>" <源> <USERNAME>@127.0.0.1:<目标>`
  - sftp `sftp -P <端口> <USERNAME>@127.0.0.1`
  - 地址 `127.0.0.1:<端口>`
  - `<USERNAME>` 原样保留,复制后由用户替换(不配置用户名)。**(用户定)** 底部只有「完成」。
- **添加 / 编辑服务器**:名称、地址、SSH 端口、登录用户、私钥(文件选择)。「测试连接」→ 实际登录一次、读取主机公钥、检查能否创建 socket 目录 → 显示 SHA256 指纹与核对命令 `ssh-keygen -lf /etc/ssh/ssh_host_ed25519_key.pub` →「指纹一致,信任」→「保存」才可用。修改地址 / 端口 / 账户 / 私钥后需重新测试并信任。名称重复或格式不对时实时提示并禁用保存。添加成功后选中这台服务器。高级项:socket 目录(默认自动)。
- **设置**(原地更新:`state` 事件不会重挂载弹窗或设备行,点击设置控件后焦点保持,进场动画只在弹窗挂载时播放 **(用户定)**):外观(显示模式 跟随系统 / 浅色 / 深色;主题色 5 种;语言 跟随系统 / 简体中文 / English)、通用(登录时启动 Tunnel;启动时自动打开上次的转发,默认开)、关于(版本)。
- **删除确认**:见 7.2。
- 所有弹窗:Esc / 点遮罩 = 取消;回车 = 主按钮。

### 7.5 设备名字重名
- 打开共享或修改设备名字时,读取该服务器上的设备信息文件;若同名且 `device_id` 不是本机 → 提示「「nas」在 X 上已被另一台设备使用,换一个名字」,禁止打开共享。同 `device_id`(本机旧记录)则正常共享。
- 无法防止两台设备同时改成同名的竞态;底层仍是后写者胜出。

### 7.6 本机 sshd 检测
- 默认不显示端口;检测本机 sshd 是否在监听及其端口(macOS「远程登录」、Linux sshd 配置或监听端口、Windows OpenSSH 服务配置),检测到即用于共享的转发目标。
- 未开启时状态行变为提示与开启方法(Windows「OpenSSH 服务器」可选功能、macOS「远程登录」、Linux 安装 openssh-server),并禁止打开共享。

## 8. 连接与重连策略

| 情况 | 行为 | 界面 |
|---|---|---|
| 服务器连不上(网络、宕机) | 指数退避 1s → 30s(±20% 抖动),稳定 60s 后重置(沿用 tunnel);系统从睡眠唤醒或网络变化时立即重试一次 | 7.3 红色横幅 + 倒计时 + 立即重试 |
| 不可恢复错误(认证失败、主机公钥不一致、socket 被拒、目录无法创建) | 停止重试。**共享服务进程不退出**,进入「失败」状态并通过控制通道报告原因,避免被服务管理器反复拉起;「重试」经控制通道触发一次重连。**(设计判断)** | 显示原因与修复方法 +「重试」 |
| 对方设备离线 | 不重连;本机端口保持监听,新连接接不通即立刻关闭 | 设备行「离线」;已开转发显示「离线,上线后恢复」 |
| 共享服务连不上 | 服务内部按上面两类处理 | 共享首行状态 + 错误说明 |
| 用户断开服务器 | 关闭该服务器连接,停止共享服务与转发,保留开关状态 | 7.3 灰色横幅 |

## 9. tunnel 仓库需要的改动

1. **设备信息文件**:共享端连上后写 `<name>.json`(字段见 6.1);本机 `device_id` 的生成与保存。
2. **设备列表 API**:列出某服务器上的设备(json 内容 + 在线探测),供桌面与 gomobile 复用。
3. **多转发会话 API**:一条 SSH 连接上动态增删多个 `LocalForwardUnix`(见 5.2)。
4. **`tunnel install / status / uninstall`**:
   - `--mode system|user` 必填;`status` / `uninstall` 不写时自动查找已安装的那种;`--profile`(服务器名称)可选:不写时自动选择已安装的那个服务,已安装多个则必须用 `--profile` 指定。
   - system 模式非 root 时自动 `sudo` 重新执行自身(原样带参数);无交互终端时报错并提示。user 模式以 root 运行时报错。**(用户定)**
   - install 先校验配置并实际连一次 VPS,失败即报错不安装;复制程序到固定位置;system 模式把配置与私钥复制到 `/etc/tunnel/`(私钥 600);写服务定义并启动;重复执行 = 更新。
   - 支持矩阵:macOS(LaunchAgent / LaunchDaemon)、Linux(`systemd --user` / systemd 系统服务)、Windows(仅 user:**任务计划程序**「登录时运行」任务,配置失败后自动重启、不显示控制台窗口;安装后立即启动,不需要管理员权限)。**(设计判断,替代原文的注册表 Run 项:Run 项无法崩溃重启)**
   - 服务名 `tunnel-<profile>`(每台服务器一个共享服务;设备名字只存在服务配置中,`install` 重复执行换名字 = 更新)。`status` / `pause` / `resume` / `retry` / `uninstall` 按 `--profile` 定位(不给时自动选择:user / system 两种模式下只有一个已安装服务就用它,多个则报错要求指定),不再接受 `--name`。同一 profile 已以另一种模式安装时 `install` 报错,需先卸载。意外退出由服务管理器 10 秒后拉起。
   - `install --mode system` 增加 `--for-user=USER`:指定服务属于哪个用户(控制 socket 的属主;默认 `SUDO_USER`,否则当前用户)。桌面 App 以管理员权限运行 install 时用它传入当前登录用户。
   - `status --json` 输出在 `ShareStatus` 字段之外加 `mode`(`user` / `system`)。退出码:0 = 运行中,3 = 已安装但未运行(`--json` 输出 `{"installed":true,"running":false,"mode":"<mode>"}`),4 = 未安装(`{"installed":false}`),其他非零 = 出错。桌面 App 靠退出码与 JSON 判断安装 / 运行状态。
   - 新增 `tunnel set-name NAME [--mode=MODE] [--profile=P]`:经控制通道改设备名字,不重装服务;名字不合法或被占用时退出码 1。
   - 新增 `tunnel pause / resume / retry`:经控制通道操作已安装的服务(不需要 root),供脚本与无界面 Linux 使用;`status --json` 也经控制通道读取。
   - 服务进程在不可恢复错误时不退出(见第 8 节);服务定义中的自动重启只针对进程崩溃。
   - 设备改名或 `uninstall` 时,删除服务器上本机(同 `device_id`)留下的旧 `<name>.json`。
5. 原 `--user`(VPS 登录用户)参数保持不变,与 `--mode` 不冲突。
